# M4：工作目录磁盘硬配额可行性审计

最后更新：2026-07-23（北京时间）

## 结论

当前 Windows 10 Pro 工作站**不具备已部署、可供产品复用的工作目录硬配额机制**。因此本项目没有
加入目录大小轮询、定时扫描、单文件上限或“超过阈值后删除”的伪配额实现，也没有把 M4 的磁盘
硬配额标为完成。

现有 Windows Job Object 继续用于 AgentHost/Codex 进程树、进程数、提交内存、CPU 和运行时间；
它不是文件系统配额，不能限制 workspace 的实际占用字节数。

## 本机只读能力审计

在本机执行的只读检查表明：

- 系统为 Windows 10 Pro x64，工作盘为 NTFS 固定本地盘；
- `fsrmquota.exe` 不存在，`SrmSvc` 服务不存在；
- `fsutil quota query C:` 明确报告卷配额未启用；
- `New-VHD` cmdlet 不可用；
- 当前令牌的卷维护权限处于 disabled 状态；
- 代码中的 `JobObjectLimitJobMemory`、进程数、CPU hard cap 和 Job user-time 都是进程资源限制，
  没有 workspace 文件系统配额调用。

NTFS 用户卷配额即使由管理员启用，也按用户/卷而不是按本项目 workspace 目录实施，会影响同一
Windows 用户的其他写入；它不能作为当前产品的目录硬配额方案。

## 可接受的后续部署路线

以下任一路线必须由安装/运维阶段预先配置，不能由 AutoCAD 插件或 AgentHost 在运行时猜测、创建
或静默降级：

1. **Windows Server FSRM**：为仅由本产品使用的受保护 workspace 根预配目录硬配额，并提供可读的
   额度状态。产品启动时只验证既有策略；策略不存在、额度状态不可读取或根不匹配时 fail-closed。
2. **专用固定大小 VHDX/卷**：由管理员预创建、挂载并以 ACL 保证仅作 workspace 使用。该卷的固定
   容量构成真实存储上限；产品只接受经过验证的固定本地卷和受保护目录，不在运行时创建、扩容或
   共享该卷。

选择任何方案后，才可以把它接入 AgentHost 启动预检、结构化失败码、运行审计和安装/卸载文档，
并用实际写满/拒绝行为完成验证。

## 明确禁止的替代品

- 轮询目录大小、清理旧文件或在超限后才停止；
- 仅限制每个文件、JSONL 或单个请求大小；
- 把 Job memory/time/process limit 说成磁盘配额；
- 把 NTFS 按用户/卷的 quota 当作本项目目录隔离；
- 在运行时创建 VHD、修改卷配额或请求提权后继续启动。

这些措施可以作为额外卫生或资源保护，但均不能满足“可靠工作目录磁盘硬配额”。

## 证据边界与后续

证据仅记录功能是否存在与启用状态，不记录盘符容量、可用空间、用户名、路径、完整权限列表或
环境变量。它没有启动 AutoCAD、没有创建/挂载磁盘、没有修改卷配额、没有运行 Codex 或 CAD 命令。

在外部部署路线明确并可实际验证前，M4 的磁盘硬配额保持未完成，M5 CAD 写入也不能因现有
Job Object 限制而获准启用。脱敏审计记录见：
`evidence/m4-workspace-hard-quota-feasibility-20260723.json`。
